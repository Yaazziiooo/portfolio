LostTracks

Solo Game Programmer · Unity · C#

UNITY · C# · SOLO PROJECT LostTracks GAMEPLAY & SYSTEMS PROGRAMMING

About the Game

LostTracks is a third-person exploration game set in a stylized town where music has disappeared.

Players restore music by interacting with NPCs, completing challenges, collecting music tracks and delivering requested items.

Developed as an individual Unity project, LostTracks allowed me to design and implement the complete gameplay architecture in C#.

My Contributions

As the sole programmer, I designed and implemented the gameplay systems, interactions, challenges, UI, progression and audio management.

Quest System

Developed an objective-based quest system supporting multiple quests, progression states and different objective types.

NPC Interaction & Dialogue

Implemented an interaction system using IInteractable, allowing players to communicate with NPCs, collect items and activate challenges.

Inventory System

Built an inventory system for collecting and managing music tracks and items, with integration into NPC deliveries and quest objectives.

Three Gameplay Challenges

Implemented three different minigames: a timing challenge, a note collection challenge and a memory sequence challenge.

Event-Driven Architecture

Used ScriptableObject events to communicate gameplay updates between systems, reducing direct dependencies between components.

ActionStack Menu System

Developed a stack-based menu architecture to manage gameplay, main menu, pause and settings states.

Audio Management

Implemented centralized music and sound effects management, including transitions between gameplay and challenge music using audio fades.

Technical Highlights

Event-Driven Quest Progression

Quest progression is connected to gameplay events rather than relying entirely on direct communication between systems.

When players complete challenges or deliver requested items, the relevant quest objectives are updated and the UI reflects the current progression.

Reusable Interaction Interface

I used the IInteractable interface to provide a consistent interaction structure for NPCs, collectibles and challenge activators.

This allowed different gameplay objects to respond to the same player interaction system while maintaining their own behavior.

Stack-Based Game States

The ActionStack system manages transitions between gameplay and different menu states.

Each action handles its own lifecycle, making it easier to control player movement, UI visibility and cursor behavior during transitions.
